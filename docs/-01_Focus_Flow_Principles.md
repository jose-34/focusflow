# Focus Flow Principles

*The constitution. One page. Read this before any other document in `docs/`.*

These principles are immutable. Every other document in this folder, every feature, every line of code, and every AI agent working on this project is subordinate to them. If a requirement, a design, or an implementation decision conflicts with a principle below, **the principle wins** — redesign the decision, don't reinterpret the principle.

1. **Meaningful Gamification.** Every feature should motivate learning through genuine achievement, not superficial rewards. XP, levels, badges, and streaks are earned only from verified learning behavior — never from opening the app, starting a timer, or any action indistinguishable from doing nothing.

2. **Reduce Procrastination.** Every workflow should help learners start, sustain, and complete meaningful work. A feature that cannot explain how it helps a student begin sooner or stay focused longer does not belong in the product, no matter how engaging it looks.

3. **Behavioral Change.** The platform exists to build lifelong learning habits and self-regulated learners — not to maximize time-in-app. A student who needs Focus Flow less over time, because they've internalized the habit, is a success, not a churn risk to engineer against.

4. **Educational Impact First.** Educational value always takes precedence over visual appeal or feature count. A plainer feature that measurably improves learning outranks a more impressive one that doesn't.

5. **Teacher Empowerment.** AI assists teachers; it never replaces their professional judgment. Every AI-generated output is a draft a teacher can edit or reject — never an autonomous action that reaches a student or parent on its own.

6. **Student Wellbeing.** The platform encourages healthy, balanced study habits rather than constant engagement. Nothing is designed to maximize time-on-screen for its own sake, and no behavioral signal about a student is used punitively.

7. **Scalable by Design.** Every component should support future curricula, schools, and new modules without major redesign. Curricula and subjects are real, insertable data, not hard-coded categories — a new curriculum is a data-entry task, never a migration.

---

Every document from `00_Project_Philosophy.md` onward exists to elaborate these seven principles into strategy, requirements, architecture, and implementation — never to override them.
